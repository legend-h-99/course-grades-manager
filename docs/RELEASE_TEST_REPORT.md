## ما اختبر فعليًا

- الموقع الحي: الصفحة الرئيسية وسياسة الخصوصية، حماية مسارات البيانات دون جلسة، رفض المصدر الخارجي والطرق والصيغ غير المسموحة، بدء Google OAuth مع state والعودة للدومين، الدخول بكلمة المرور، حفظ الملف الشخصي وفك تشفيره، إنشاء مقرر وتقييم ومتدرب ودرجة، الدعوة والمشاركة والتعديل من الحساب الثاني، تجديد الجلسة، وتصدير Excel. قرئ ملف Excel الناتج وتحقق من وجود المتدرب الاصطناعي والدرجة 19.
- نسخة الإصدار: اختبارات المتصفح على Chrome بعرض 390 و1440 بكسل، RTL وعدم تجاوز عرض الشاشة، التنقل والتحقق من الحقول، API قائمة المقررات، استيراد CSV وExcel مع الاستدعاء بعد إعادة التحميل، البحث بالرقم التدريبي، إضافة تقييم عملي نهائي وحفظه وإعادة تحميله، قص الدرجة إلى الحد الأدنى والأقصى، وتسجيل الخروج وإخفاء البيانات الخاصة دون أخطاء JavaScript.
- Supabase: تفعيل RLS على الجداول السبعة، منع غير الأعضاء من رؤية المقرر والملف والمتدربين والتقييمات والدرجات، منع الانضمام المباشر دون دعوة، السماح للعضو بقراءة الدرجة وتعديلها، منع الاستيلاء على الملكية، حماية سجل التدقيق، وإنشاء دعوة عند إنشاء المقرر.
- استخدم حسابان مؤقتان وبريد من نطاق example.invalid، وبيانات اصطناعية فقط. حذفنا الحسابين والمقررات التي أنشأها الاختبار بعد الانتهاء، وتحققنا من عدم بقائها. قد تبقى أحداث التدقيق التشغيلية بحسب سياسة الاحتفاظ.

## الإصلاحات الناتجة عن الاختبار

1. أصلحنا trigger إنشاء دعوة المقرر: كان يفترض أن course_id قيد فريد، بينما مخطط الإنتاج يستخدم id مفتاحًا أساسيًا ويتيح عدة دعوات. طبق الترحيل fix_course_invite_trigger على Supabase وأعيد اختبار SQL بنجاح.
2. أضفنا مسار قائمة المقررات وتحقق العضوية عند طلب مقرر محدد؛ سابقًا كان المسار يرجع 405 ويتجاهل اختيار المقرر.
3. أصلحنا تسجيل الخروج ليرسل JSON، ولينظف لوحة المستخدم حتى عند تعذر إلغاء الجلسة على الخادم.
4. أجلنا إظهار مساحة العمل حتى اكتمال تحميل بيانات الحساب، لمنع الاستيراد على حالة فارغة ثم فقد التغييرات عند انتهاء التحميل.
5. أصلحنا Enter في حقل البريد ليستخدم تسجيل الدخول/إنشاء الحساب بدل إرسال OTP.
6. حدثنا حزم أداة النشر وأعدنا الفحوص حتى أصبح فحص الحزم كاملًا خاليًا من التنبيهات.

## ما لم يتحقق بعد

- حماية كلمات المرور المسرّبة معطلة بحسب مستشار Supabase. يلزم تفعيلها من Authentication. توجد أيضًا تحذيرات لسبع دوال SECURITY DEFINER مقصودة للعضوية والدعوات؛ روجعت تعريفاتها واختبر العزل، ولم نلغ صلاحياتها لأن التطبيق يحتاجها.
- اختبر بدء Google OAuth والتحقق من state؛ لم يكمل مستخدم حقيقي تسجيل الدخول داخل Google. لم تختبر قابلية تسليم رسائل تأكيد البريد وOTP واستعادة كلمة المرور إلى صندوق بريد حقيقي.
- اختبار المعاينة استخدم Worker المبني وSupabase الحقيقي بمفتاح تشفير مؤقت خاص بالبيانات الاصطناعية؛ ليس اختبارًا لأسرار Cloudflare أو نشر النسخة على بنيته الفعلية. لم نغيّر مفتاح تشفير الإنتاج.
- الحساب المحلي في Cloudflare يفتقد صلاحيات Workers. لم يتحقق وجود أسرار Worker أو تنفيذ نشر فعلي بهذه الجلسة. آخر فحص لأسرار GitHub في هذه الجلسة لم يتضمن أسرار Cloudflare للنشر عبر Actions؛ يوجد أيضًا مسار Workers Builds مرتبط بالمستودع ويجب التأكد من الفرع الذي ينشر منه.
- يوجد تحذير أداء من Smart Placement مع run_worker_first؛ لا يعد فشل بناء، ولم يجر اختبار تحميل واسع أو اختبار استعادة نسخة احتياطية.

## إعادة التشغيل

يجب تجهيز حسابين اصطناعيين مؤقتين في Supabase مع ملف محلي خارج Git، يمثل مصفوفة كائنات تحتوي id وemail وpassword. يقبل الاختبار نطاق example.invalid فقط؛ الاختبار يعدل بيانات الحسابات المحددة. شغل على مساحة اختبار، ونظف المقررات والحسابات بعد الانتهاء.

```sh
npm test
npm run test:security
npm audit
npx wrangler deploy --dry-run
RELEASE_BASE_URL=https://sanadapp.pro RELEASE_TEST_ACCOUNTS=/path/outside/git/accounts.json node scripts/release-check.mjs
RELEASE_BASE_URL=https://sanadapp.pro RELEASE_TEST_ACCOUNTS=/path/outside/git/accounts.json node scripts/release-browser-check.mjs
```

يتطلب اختبار المتصفح Chrome مثبتًا. شغّل scripts/release-check.mjs أولًا لتجهيز المقرر ثم الاختبار الموسع. نتائج المتصفح تحفظ في /tmp ولا تتضمن كلمات المرور. شغّل supabase/tests/data_security.sql عبر اتصال إداري؛ بياناته الاصطناعية داخل معاملة تنتهي بالتراجع.

مرجع حماية كلمات المرور: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection
